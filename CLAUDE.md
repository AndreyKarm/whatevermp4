# CLAUDE.md

Self-hosted watch-party app. Users upload videos (or add torrents); a worker transcodes them to HLS and stores them in S3, and people watch together in synced rooms. There are no accounts: users pick a nickname, which the frontend sends with every request.

## Layout

```
docker-compose.yml   full stack: rustfs (S3), postgres, movie (API), worker, web
.env.example         compose variables (copy to .env)
backend/             Go module `liotom/whateverserver`
  cmd/api/           HTTP + WebSocket server (binary: movie-server)
  cmd/worker/        job runner for transcoding and torrents (binary: movie-worker)
  internal/
    config/          env-var config (Config.Load)
    db/              pgxpool connect
    httpapi/         chi router and REST handlers (media, uploads, torrents, rooms, playback)
    rooms/           in-memory watch-party hub, WebSocket protocol, state persistence
    jobs/            Postgres-backed job queue (Enqueue / Claim / Done / Fail)
    transcode/       ffprobe → plan → ffmpeg HLS (fMP4), subtitle/font extraction, poster
    torrent/         anacrolix/torrent downloader that imports video files as media
    storage/         S3 client (multipart presign, get/put, delete prefix), content types, name helpers
  migrations/        SQL generated by drizzle-kit from the frontend schema; run by postgres initdb on a fresh volume
frontend/            SvelteKit 3 + Svelte 5 (runes) + Tailwind 4, adapter-node, pnpm
  src/env.ts         declared env vars (DATABASE_URL, PUBLIC_API_URL)
  src/lib/
    api.ts           apiFetch<T>() / apiPost<T>(): prefix PUBLIC_API_URL, add the X-Nickname header
    nickname.svelte.ts  nickname state in localStorage, plus a context helper
    room.svelte.ts   RoomSocket: WebSocket client, reconnect, server clock offset, target position, canControl
    upload.svelte.ts S3Uploader: browser → S3 multipart upload via presigned URLs, with progress
    types.ts         API response types and RoomIn/RoomOut WS messages (mirror the Go structs)
    components/      Player.svelte (hls.js, drift correction, host controls, subtitles), Uploader.svelte, UrlImport.svelte, Torrents.svelte
    server/db/       drizzle schema.ts (source of truth for the DB schema) and client
  src/routes/        / (library, rooms, torrents), /rooms/[id] (player, members, chat, host settings)
```

## How it fits together

- **Upload:** `POST /api/uploads/init` creates a `media_files` row (`uploading`) and presigned part URLs. The browser PUTs 64 MB parts straight to S3, then `POST /api/uploads/{id}/complete` finishes the upload, sets `processing` and enqueues a `process` job.
- **Torrent:** `POST /api/torrents` stores a magnet link or base64 metainfo and enqueues a `torrent` job. The worker downloads only the video files (skipping "sample"), uploads each one to `raw/{id}/…`, inserts `media_files` rows and enqueues a `process` job for each.
- **Link import:** `POST /api/imports` (`url`, optional `name`, `referer`) creates a `media_files` row (`downloading`) and enqueues an `import` job. The worker remuxes the `.m3u8` stream into MKV with `ffmpeg -c copy` (network protocols only, via `-protocol_whitelist`), uploads it as the raw file and enqueues `process`. Master playlists use ffmpeg's default stream pick (best video plus one audio).
- **Process:** the worker downloads the raw file, then runs `ffprobe` → `BuildPlan` → `ffmpeg`. It copies H.264 8-bit video and AAC ≤2ch audio as is and re-encodes everything else. It writes `hls/{id}/master.m3u8`, segments, `subs/*.vtt|.ass`, `fonts/` and `poster.jpg`, then marks the media `ready`.
- **Playback:** media responses include `playbackUrl` = `/play/{hmacToken}/{id}` (12h TTL, signed with `PLAYBACK_SECRET`). The client appends `/master.m3u8`, and the API proxies the files from S3 with Range support.
- **Rooms:** the WebSocket is at `/api/rooms/{id}/ws?nickname=…`. Client → server: `play|pause|seek|rate|change_media|buffering|chat|ping`. Server → client: `state|members|chat|pong|error` (see `rooms/messages.go`). The server is authoritative: position = `position + (now - updatedAt) * rate` while playing. If any member is buffering, the room pauses and sets `holding`. Only the owner (matched by nickname) can control playback unless `everyone_controls` is on. The hub writes dirty state to `rooms.state` every 10s and evicts empty rooms.
- **Jobs:** the `jobs` table is claimed with `FOR UPDATE SKIP LOCKED`. A job gets 3 attempts with a 30s backoff. On startup the worker requeues `running` jobs, which assumes a **single worker instance**.

## Running

### Full stack (Docker)

```bash
cp .env.example .env
docker compose up --build
```

Ports: web 3000, API 8088, RustFS S3 9044 (console 9045), Postgres 5432.

On a fresh `pgdata` volume, Postgres creates the schema from `backend/migrations/*.sql`. For an existing database, or after changing `schema.ts`, push the schema from the frontend:

```bash
cd frontend && DATABASE_URL=postgres://movieuser:<pw>@localhost:5432/local pnpm db:push
```

After a schema change, also run `pnpm db:generate` (writes to `backend/migrations`) so fresh installs pick it up.

### Backend locally

Requires Go 1.27+, and `ffmpeg`/`ffprobe` on PATH for the worker. Config is read **only from the process environment** (no .env loader), so export the values from `backend/.env.example` first. Run postgres and rustfs with `docker compose up db rustfs`.

```bash
cd backend && go run ./cmd/api
```

```bash
cd backend && go run ./cmd/worker
```

Checks: `go build ./...`, `go vet ./...`. There are no tests yet.

### Frontend locally

pnpm with `engine-strict`. Set `DATABASE_URL` and `PUBLIC_API_URL` (e.g. `http://localhost:8088`) in `frontend/.env`.

```bash
cd frontend && pnpm install && pnpm dev
```

Other scripts: `pnpm build`, `pnpm check` (svelte-check), `pnpm lint` (prettier + eslint), `pnpm format`, and `pnpm db:push|db:generate|db:migrate|db:studio` (drizzle-kit).

## Conventions

### Go
- Use raw SQL through `pgxpool`, with no ORM. Column names are snake_case and must match `frontend/src/lib/server/db/schema.ts`.
- Handlers are methods on `httpapi.Server`. Respond with `writeJSON` / `writeErr` (`{"error": "..."}`); mutations without a body return `204`.
- JSON fields are camelCase. Optional columns are pointer fields with `omitempty`. JSONB columns use `json.RawMessage` in API structs.
- PATCH handlers take pointer fields and use `COALESCE($n, col)`. When "omitted" and "null" must differ, use `optInt` (see `PATCH /api/media/{id}`, which also re-parses season/episode from a new filename).
- IDs are `uuid.NewString()` stored as `text`. The only exception is `jobs.id`, which is a bigserial.
- The caller's identity is `nickname(r)`, which URI-decodes the `X-Nickname` header and passes it through `rooms.CleanNickname` (trimmed, at most 32 runes, default "Anonymous"). Nothing is authenticated. Room settings and deletion check the nickname against `owner_name` (`requireRoomOwner`).
- When a handler changes a room that may be loaded in the hub, update the hub too (`Hub.SetEveryoneControls`, `Hub.Remove`). The hub otherwise keeps its own copy until the room is evicted.
- Status strings: media `uploading|downloading|processing|ready|failed`, torrent `queued|downloading|importing|done|failed|cancelled`, job `queued|running|done|failed`.
- S3 key layout: `raw/{mediaId}/{SafeName(filename)}` for originals and `hls/{mediaId}/…` for transcoded output.
- Long-running work belongs in the worker as a job type, not in a request handler.
- Lock in `rooms`: methods ending in `Locked` expect `Room.mu` to be held.

### Frontend
- Use Svelte 5 runes only (runes mode is forced in `vite.config.ts`). Shared reactive state lives in `*.svelte.ts` classes.
- Import from `#lib/...` with explicit `.ts` extensions (e.g. `#lib/api.ts`). Read env through `$app/env/public` / `$app/env/private`, declared in `src/env.ts`.
- Make all backend calls through `apiFetch` so the nickname header is sent. Build internal links with `resolve()` from `$app/paths`.
- When a Go JSON struct changes, update `src/lib/types.ts`. When a table changes, update `src/lib/server/db/schema.ts` (the Go code does not define the schema).
- Styling follows the fielv-store look and is defined in `src/routes/app.css`: Montserrat (served from `static/fonts`), dark `bg`/`secondary` surfaces, pink `primary`. Use the theme tokens as Tailwind utilities (`bg-secondary`, `text-primary`, `border-border`, `text-muted`, `text-accent`, `text-warn`) and the component classes (`panel`, `panel-title`, `section-title`, `label`, `input`, `btn btn-primary|btn-outline`, `btn-icon`, `btn-round`, `badge`, `meta`, `progress`, `modal-overlay`/`modal-content`) instead of raw Tailwind palette colors. Icons come from `@lucide/svelte`.
- Prettier settings: tabs, single quotes, no trailing commas, width 100.

## Known gaps / gotchas

- `PUBLIC_API_URL` is read at runtime (not inlined at build), so it can be changed in compose without rebuilding. `BACKEND_URL` is also passed to `web` but nothing reads it yet.
- Browser multipart upload needs the bucket CORS to expose `ETag`. `storage.New` sets this on startup from `ALLOWED_ORIGINS` and only logs if the S3 server rejects it.
- The room WebSocket is closed with code 1008 when the room doesn't exist or is deleted. The frontend treats that as final and doesn't reconnect.- `S3_ENDPOINT` is used by the server for its own S3 calls. `S3_PUBLIC_ENDPOINT` must be reachable from the browser because presigned upload URLs are signed against it.
